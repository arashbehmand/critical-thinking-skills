Toolbox for AI agents · v1.4 branch

critical-thinking-mcp

A set of thinking procedures an agent follows, a small math server that does the arithmetic those procedures need, and two harness hooks. It gives the agent the habits a careful engineer or analyst uses: split the problem, test the explanation, compute instead of guess, and check the work before trusting it.

Method 20

Skills

Written procedures the agent follows. A controller picks the smallest useful one for the problem, or none. When a step needs a judgment, the skill has the agent ask a fresh subagent that never saw the draft.

Small scripts the agent harness runs at fixed moments. One hands the controller to the agent when a request looks consequential. One stops a verdict from shipping without its checklist file.

Math server

An MCP server of pure functions: rank hypotheses, combine estimates, score calibration, evaluate an argument tree, find which premise a conclusion rests on. Same input, same output, rule printed with the result.

src/ctmcp/

Every result says where its strength came from. The package keeps three kinds of help apart, because polished prose blurs them:

Evidence

Something from outside the model: a source, an observation, a resolved outcome.

Computation

Code, a solver or a formula did the work, so it is exact about what it was given.

Structure

The problem was split, reframed or seen by a fresh mind. Useful, but it adds no new facts.

Hooks

Two things a skill cannot do for itself

A skill is advice. The model most likely to skip it is the confident one. These run outside the model. Both fail open: if anything goes wrong, the session carries on untouched.

controller_nudge.py

Makes the skills get used

Runs when you send a message. If the wording looks consequential (a decision, an estimate, a "why did", a "never", a risk), it adds one line asking the agent to run the controller. Once per session at most. Every decision is logged, so you can count how often it engages.

verdict_gate_stop.py

No verdict without its checklist

Runs when the agent tries to finish. If the reply ships a verdict ("Recommendation:", "Decision:", go/no-go) and no gate file was written this session, it blocks once and asks for the gate. Skipping items is allowed; skipping them silently is not.

What we measured

It helps weaker models, when they are told to use it

Task: math word problems with a needed number removed. The right answer is "this can't be solved". Every comparison was written down and hashed before it ran, and each has a known-good control to prove the test could see an effect.

What the numbers say

  • The gain is not just extra effort. Thinking harder, or being told to reason at length, does not close the gap.
  • It is not the ceremony of opening a skill. A fake "garden planner" skill, opened every time, added nothing for Gemini.
  • The weaker the model, the bigger the gain: about 10 points for Haiku, about 33 for Gemini.
  • An installed skill that nobody points at does nothing. That is why the nudge hook exists.

What they do not say yet

  • One kind of task only: spotting that a question cannot be answered.
  • Two weaker models; no working test on a frontier model.
  • The newest acts, ct-formalize and ct-sanity-check, have only a small behaviour probe: with them, Haiku wrote and ran code on 10 of 10 hard problems and got all 10 right, against 9 of 10 without. Too few runs to call it a gain.
  • Whether the nudge hook works as well as a direct instruction is not measured.
Where it won't help

Leave it off for these

  • Quick, ordinary requests. Renaming a variable or answering a lookup needs no procedure. The controller's most common correct answer is to do nothing.
  • Problems the model already gets right. A strong model on an easy task has no room to improve; the skills add cost and length.
  • Missing facts. Structure cannot supply evidence. If the needed fact is not available, the right output is a named gap, not a better-looking guess.
  • Wrong models, computed exactly. A solver is exact about what it was given. If the model of the problem is wrong, the answer is exactly wrong. The sanity check reduces this; it does not remove it.
  • Proof that the procedure ran. A written receipt shows a receipt was written. The hooks and the math server narrow this gap; they do not close it.
  • Human judgment calls. Values, priorities and irreversible actions go back to you, not to a procedure.
Install

Three steps, each optional

1. The skills

Copy the skill folders into a project, or into your home folder for every project. They work without the server; their scripts use the Python standard library only.

cp -r skills/* your-project/.claude/skills/
# or, for every project:
cp -r skills/* ~/.claude/skills/

2. The math server

claude mcp add critical-thinking -- \
  uv run --directory /path/to/critical-thinking-mcp ctmcp

3. The hooks

Add to .claude/settings.json. Use full paths.

{
  "hooks": {
    "UserPromptSubmit": [{"hooks": [{"type": "command",
      "command": "python3 /path/to/hooks/controller_nudge.py"}]}],
    "Stop": [{"hooks": [{"type": "command",
      "command": "python3 /path/to/hooks/verdict_gate_stop.py"}]}]
  }
}
